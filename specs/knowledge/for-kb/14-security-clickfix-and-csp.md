# 安全：假验证码（ClickFix）与站点防护

## 这是什么

攻击者若能改写网站返回的网页，可能插入假的 “I'm not a robot” / “完成验证” 对话框，把恶意命令放进剪贴板，再诱骗你打开 **终端（Terminal）** 粘贴执行。这叫 ClickFix 一类手法。正规人机验证**只在浏览器内完成**，从不会要求你打开系统终端或运行命令。

## 对使用者 / 管理员

- 在 `kb.agent-mate.ai`（或任何站点）上：若出现要求打开 Terminal、按 ⌘V 再回车的“验证”，**立即关闭页面，不要执行**。  
- 管理台签发的 API Key、密码、邮件重置链接按敏感信息保管；怀疑泄露时在管理台吊销 Key 并改密。  
- MCP / ChatBox 配置只填官方路径：`https://kb.agent-mate.ai/mcp` 或 `/sse`，不要轻信陌生域名上的“安全验证”页。

## 本站已做的防护（摘要）

- 生产 **kb-web** 使用带 **一次性 nonce** 的 Content-Security-Policy：浏览器拒绝无 nonce 的内联脚本和 `data:` 脚本（正是此类挂马常用手法）。  
- 生产环境限制页面脚本的外连范围（`connect-src` 以本站为主），降低恶意脚本外联拉取第二段代码的能力。  
- 前端框架（Next.js）须保持在已修复已知远程代码执行漏洞的版本；过期次要版本不要继续跑生产。

## 运维抽查（可选）

怀疑页面被改时，可在本机执行（不要访问可疑“验证”弹层）：

- 查看响应头是否仍有 `content-security-policy` 且含 `nonce-`。  
- 页面源码中不应出现 `data:text/javascript;base64`。  
- `https://kb.agent-mate.ai/healthz` 应返回正常 JSON；若首页能开而 healthz 失败，多半是反代未刷新，而非要你去终端“验证”。

## 非目标

- 不替代杀毒或本机安全习惯。  
- 不详述恶意载荷或复现攻击步骤。  
- 密钥与主机口令不写入知识库正文。
