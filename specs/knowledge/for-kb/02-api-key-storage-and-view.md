# API Key：密文存库、管理台查看与吊销

## 问题

若库内只存 Key 的哈希，管理员无法在列表再次展示完整明文（哈希不可逆）。产品需要「查看」时，必须改存储，但不能为了方便把明文落库。

## 做法

- **鉴权**：`key_hash` = SHA-256(pepper + 明文)；请求只比对哈希。  
- **管理查看**：另存 `key_ciphertext`（AES-256-GCM，含 nonce）；签发与重签时写入。  
- **加密密钥**：环境变量 `API_KEY_ENCRYPTION_SECRET`（生产必设）。本地未设时可回退派生自 pepper，仅便于开发。  
- **查看 API**：管理员会话 `GET` 指定 Key，解密返回姓名与明文；无密文的历史行提示重签。  
- **列表**：默认只显示前缀与状态；完整明文只在查看/签发结果页。

## 吊销

吊销是软状态：Key → revoked，用户 → disabled；不硬删用户（避免级联删知识）。列表只展示仍 active 的 Key。

实现上：用路径中的 key id（任意状态）解析 `user_id`，再吊销该用户下全部 active Key。这样重签后客户端若仍拿旧 id，不会变成空操作。

## 运维注意

- 轮换 `API_KEY_ENCRYPTION_SECRET` 或 pepper 会导致旧密文无法解密或鉴权失败；生产签发后勿随意改。  
- 日志禁止打印明文 Key。  
- 备份库 + 加密密钥同时泄露 ≈ 可还原 Key；权限与密钥保管要按敏感配置对待。
